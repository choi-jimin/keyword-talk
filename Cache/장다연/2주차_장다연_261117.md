# Redis 데이터 조회 최적화와 원자적 처리

## 1. 가져올 데이터가 많다면? — Hash Tag + MGET / Pipeline

### MGET
- 여러 String Key를 **하나의 명령으로 조회**하는 Redis 명령어
- `GET`을 여러 번 호출하는 것보다 네트워크 왕복(RTT)을 줄일 수 있음
- 결과는 요청한 Key 순서대로 반환되며, 없는 Key는 `nil` 반환
- 시간 복잡도: `O(N)` (조회하는 Key 개수 기준)

```redis
MGET user:{1001}:name user:{1001}:age user:{1001}:grade
```

### Redis Cluster와 Hash Tag
- Redis Cluster는 Key를 16,384개 Hash Slot 중 하나에 배치하고, Slot을 여러 노드에 분산함
- Cluster의 `MGET`은 조회 대상 Key들이 **같은 Slot**에 있어야 함
- `{}` 안의 문자열만 해싱하는 Hash Tag를 사용하면 관련 Key를 같은 Slot에 배치할 수 있음

```text
user:{1001}:name
user:{1001}:age
user:{1001}:grade
```

위 세 Key는 `{1001}`을 기준으로 같은 Slot에 배치됨.

> 주의: 모든 Key에 같은 Hash Tag를 사용하면 특정 Slot/노드에 부하가 집중되는 Hot Spot이 생길 수 있음. 함께 조회할 데이터끼리 적절히 묶어야 함.

### MGET과 Pipeline의 차이
- **MGET**: 여러 Key를 조회하는 Redis 명령어 하나
- **Pipeline**: 여러 Redis 명령어를 모아 한 번에 전송하는 통신 최적화 방식
- Pipeline은 서로 다른 명령어도 묶을 수 있지만, 묶음 전체의 원자성을 보장하지 않음
- Cluster에서 서로 다른 Slot의 명령은 Cluster-aware 클라이언트가 노드별로 분배해야 함

```redis
# MGET: 명령어 하나
MGET user:1001 user:1002 user:1003

# Pipeline: 여러 명령어를 묶어 전송
GET user:1001
HGET user:1002 name
GET user:1003
```

## 2. 원자적 처리가 필요하다면? — Lua Script

### 원자성이란?
여러 작업이 하나의 작업처럼 실행되어, 실행 중간에 다른 명령이 끼어들지 못하는 성질.

### 문제 상황: 재고 차감
재고가 1개일 때 두 요청이 동시에 다음 작업을 수행하면 초과 판매가 발생할 수 있음.

1. 재고 조회
2. 재고가 있는지 확인
3. 재고 차감

조회와 차감 사이에 다른 요청이 끼어드는 경쟁 상태(Race Condition)가 원인.

### Lua Script로 해결
Redis는 Lua Script를 하나의 원자적 실행 단위로 실행함. 재고 확인과 차감을 한 스크립트 안에서 처리할 수 있음.

```lua
local stock = tonumber(redis.call('GET', KEYS[1]))

if stock and stock > 0 then
    redis.call('DECR', KEYS[1])
    return 1 -- 차감 성공
end

return 0 -- 재고 없음
```

- 재고가 있으면 차감 후 성공 반환
- 재고가 없으면 차감하지 않고 실패 반환
- 스크립트 실행 중 다른 Redis 명령이 끼어들지 못함

### 주의사항
- Lua Script 실행 중 다른 명령이 실행되지 않으므로 스크립트는 짧고 가볍게 작성
- 오류가 발생해도 앞서 수행한 쓰기 작업이 자동 롤백되는 것은 아님. 변경 전에 검증할 것
- Redis Cluster에서는 스크립트가 접근하는 Key를 `KEYS`로 전달하고, 관련 Key들은 같은 Slot에 있어야 함

## 3. 한눈에 비교

| 상황 | 기술 | 핵심 목적 |
|---|---|---|
| 같은 Slot의 여러 String Key 조회 | MGET | 네트워크 왕복 감소 |
| 여러 종류의 Redis 명령을 묶어 전송 | Pipeline | 통신 효율 개선 |
| Cluster에서 함께 조회할 Key 배치 | Hash Tag | 동일 Slot 배치 |
| 조건 확인과 데이터 변경을 함께 처리 | Lua Script | 원자성·동시성 제어 |

## 핵심 요약

- **데이터 조회 최적화:** Hash Tag로 함께 조회할 Key를 같은 Slot에 배치하고, MGET으로 한 번에 조회한다.
- **여러 명령 전송 최적화:** Pipeline으로 명령들을 묶어 보내되, 원자성은 별도로 보장되지 않는다는 점에 유의한다.
- **원자적 처리:** 재고 차감처럼 조건 확인과 변경이 함께 이루어져야 하는 작업은 Lua Script로 처리한다.

> 기억하기: MGET은 여러 Key를 조회하는 **명령어**, Pipeline은 여러 명령을 묶는 **통신 방식**, Lua Script는 여러 작업을 원자적으로 실행하는 **서버 측 스크립트**다.
