# 스터디 회고

## 공부한 것 외에 스터디에서 나왔던 내용
- **파이프라이닝**: 여러 명령을 응답을 기다리지 않고 한 번에 보내서 왕복 횟수를 줄임.
  MGET과 달리 서로 다른 명령도 묶을 수 있지만, 원자적이지는 않음 (Lua와의 차이).
- **SCAN 계열**: Redis는 명령을 하나씩 처리하므로 KEYS *, HGETALL 같은 명령은
  데이터가 많으면 서버 전체를 멈춤. SCAN 계열은 커서로 끊어서 가져와 이를 방지.
  단, 순간의 스냅샷이 아니라서 중복·누락이 생길 수 있음.
- **키 범위 vs 해시 파티셔닝**
  - 키 범위: auto increment ID로 나누면 새 데이터가 마지막 노드에만 몰림.
    (예: 어제 1~100은 노드1, 오늘 101~200은 노드2 → 오늘 가입자 조회·저장이 노드2에 집중)
    대신 범위 조회는 노드 몇 개만 보면 돼서 빠름.
  - 해시: 시간 순서와 상관없이 골고루 분산. 대신 범위 조회는 모든 노드를 뒤져야 함.
  - Redis Cluster는 키 단위 조회가 대부분이라 해시(슬롯)를 택함.
- **샤딩 / 리샤딩**: 샤딩은 데이터를 노드에 나눠 담는 것,
  리샤딩은 노드를 늘리거나 줄일 때 슬롯과 데이터를 옮기는 것.

## 이전에 배운 것과의 연결
- 파이프라이닝 ↔ MGET ↔ Lua: 셋 다 왕복을 줄이지만
  | | 묶을 수 있는 것 | 원자성 |
  |---|---|---|
  | MGET | 같은 종류 읽기 | 같은 슬롯이면 ✅ |
  | 파이프라이닝 | 서로 다른 명령 | ❌ |
  | Lua | 서로 다른 명령 + 조건 분기 | ✅ |
- SCAN ↔ 싱글 스레드 ↔ slow command: 오래 걸리는 명령 하나가 전체를 막는다는 같은 원리.
  (MGET 키 너무 많이, 긴 Lua 스크립트, KEYS *)
- 해시 파티셔닝 ↔ Redis Cluster 슬롯 ↔ consistent hashing
- 리샤딩 ↔ 슬롯 번호는 고정, 담당표만 바뀌고 넘긴 슬롯의 데이터만 이동
